# État réel du projet

À tenir à jour à chaque changement : ce qui est fait, ce qui n'a jamais tourné pour de vrai, ce qui manque.

| État | Quoi |
|---|---|
| Fait, testé hors réseau (~560 tests) | Agent LLM qui gère son loyer (A3/A2 : prompt version 2, réveil choisi par l'agent, palier économie ; jamais essayé avec un vrai LLM), loyer payé par la mise (A1 : kill switch, plus-haut et paliers sur l'equity nette du coût d'API, jamais observé avec un vrai LLM), backtest (rejeu, stratégies de comparaison, commande `backtest`), moteur, garde-fous, paliers de risque, kill switch, exchange papier, budget d'inférence, agent LLM (vrai SDK + transport HTTP simulé), profils, lanceur `up`, verrou anti-double-bot, interface web (vérifiée dans Chromium), scripts `.sh` (Linux) |
| Vérifié sur le PC de Pierre (Windows 11, Python 3.12, 2026-10-04) | Suite au vert : 465 passent, 17 ignorés (tests à signaux POSIX du lanceur, tests des `.sh` faute de `sh`). Sous Windows, l'arrêt propre est couvert par `test_stopper.py` (`--stop-on-stdin`, de bout en bout) ; **l'arrêt de `tradeagent up` et les scripts `.sh` n'y sont couverts par aucun test** |
| Exécuté pour de vrai, **une seule fois** (2026-10-04) | `CcxtPriceFeed` sur Bitvavo : un cycle du profil `hold` (étape 0.1 passée), via `python -m tradeagent` et via `scripts\paper.bat`. Message « paire absente » vérifié contre le vrai ccxt. Rien sur la durée. `tradeagent backtest --days 30` : historique téléchargé sur Bitvavo et rejoué une fois, cache relu au second lancement. Une vie `hold` est ouverte dans `data/paper-hold.db` |
| Exécuté pour de vrai, **une seule fois** (2026-10-04, par Pierre) | Vrai LLM en backtest : `backtest --agents hold,buyhold,llm --days 2 --max-api-eur 0.20`. 3 appels payés, 0,0051 € au total, soit **0,0017 € par appel** (environ 1 210 tokens en entrée, 120 à 150 en sortie, Haiku 4.5). L'agent s'est servi de son réveil (sommeils de 4 h à 24 h avec réveil sur mouvement de 2 à 3 %) : 3 appels au lieu de 48. Aucun ordre passé, donc rien sur sa capacité à trader. Deux erreurs de lecture relevées dans ses raisonnements : il prend 0,3 % pour le coût d'un aller-retour (c'est par sens), et il lit le plafond d'API du jour comme un budget à préserver |
| Exécuté pour de vrai (2026-10-04, par Pierre), prompt version 4 | Backtest réel de 30 jours (période où `buyhold` fait +9,56 %) : l'agent `llm` finit à **−2,54 %** net (equity 50,08 €, loyer 1,353 €). 665 appels sur 720 possibles (il ne dort presque plus : 28 sommeils demandés), 0,00203 € par appel, **122 réponses en prose au lieu du JSON** (18 %, 0,38 € payés pour rien), un seul aller-retour (10 € d'ETH, environ +0,08 €). Conclusion : sur ce mois, le loyer coûte seize fois ce que le trading rapporte ; le format de réponse n'est pas tenu ; l'agent est resté en cash pendant une hausse de 12 % |
| Exécuté pour de vrai (2026-10-04, par Pierre), prompt version 5 | Même mois, après appels sur évènement et format de réponse imposé : l'agent `llm` finit à **+4,75 %** net (equity 52,53 €, loyer 0,159 €) contre +9,35 % pour `buyhold`. 69 appels, 69 réponses JSON valides, 0,0023 € par appel. Deux achats de 10 € jamais revendus : un achat-conservation à mi-dose sur un mois de hausse, pas encore une preuve qu'il sait choisir. Reste à le juger sur un mois de chute (fin 2026-06-06, marché −27,6 %) et un mois plat (fin 2026-08-05) |
| Fait, **jamais exécuté pour de vrai** | Vrai appel à l'API Anthropic en `run` (profil `llm`), les autres scripts `.bat`, interface sur Firefox/Safari. Dans l'environnement de dev d'origine, le réseau bloque les exchanges : le flux réel ne se teste que sur le PC de Pierre |
| Fait, vérifié sous Windows seulement | Application de bureau, visionneuse (F1), superviseur (F2) et notifications de bureau (F3) : 48 tests Node + lancements réels avec capture d'écran. Version portable (F4) : construite et lancée pour de vrai une fois (2026-10-04), dans un dossier vierge du même PC, donc avec Python 3.12 déjà installé ; **jamais essayée sur un PC sans Python, avec un Python trop ancien, ni hors ligne** (ces cas ne sont couverts que par des tests simulés), et les boîtes de dialogue de l'installation n'ont jamais été vues. Notifications : la lecture des instantanés tourne pour de vrai, mais **aucune notification n'a été vue à l'écran** et aucune vraie transition (mort, `halted`, palier, budget) n'a été observée hors tests. Jamais lancée sous Linux/macOS ; le verrouillage des pages (navigation, requêtes externes, permissions) est codé mais **pas testé automatiquement** ; menus de la zone de notification et boîtes de dialogue jamais regardés à l'œil |
| **Pas fait** | Mode réel (adaptateur d'exchange authentifié + quarantaine),  notifications hors du PC (D1), export CSV, service/daemon, CI, historique des vies. |

Premier réflexe si quelque chose « ne marche pas » : `scripts/paper.sh hold --max-cycles 1` (prix réels, gratuit). Si ça échoue, c'est le flux ccxt, jamais testé en vrai.
